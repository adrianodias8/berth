# Memory after a workload, 2026-10-25

M2 Max, 32 GB, macOS 27; berth 7.2.12 kernel with Podman and nerdctl on,
OrbStack 2.2.5. `bench/sysmem.sh`: system-wide anonymous + wired +
compressor memory against both engines stopped; the workload writes every
page of 4 GiB in a container. The Mac's other apps move these by a few
hundred MB.

| | idle | peak | 1 min after | 3 min after |
|---|---|---|---|---|
| berth, before | +2391 MB | +3930 MB | +3909 MB | +3722 MB |
| berth, `.metadata_never_index` on the `~/Berth` share | **+1876 MB** | **+3365 MB** | +3367 MB | **+3137 MB** |
| OrbStack | +1672 MB | +5107 MB | +5120 MB | +4991 MB |

Neither engine gives the workload's memory back within 3 minutes. berth's
peak is lower: the balloon caps the guest, which then swaps the workload's
pages to zram (lz4), where these compress well.

VM process footprint a minute and a half after start: 2140-2224 MB before,
1841 MB after.

## Why berth can't give it back

- Virtualization.framework's traditional balloon leaves touched pages with
  the VM process: a 14 GiB inflation didn't change the footprint, and
  macOS memory pressure didn't take those pages either.
- There's no free page reporting (OrbStack's kernel uses it, with its own
  hypervisor), and the macOS 27 custom Virtio API only copies buffers: it
  can't discard guest memory.
- `init_on_free` (so freed pages are zeros, which macOS compresses to
  nothing) also zeroes all memory at boot and everything a balloon deflate
  returns, in 7.2: it would make macOS back the whole VM.

## The idle fix

macOS indexes a newly mounted SMB volume: it walked every Docker volume in
`~/Berth` (here a kernel build volume of several source trees), held
~16,400 directories open and left the connection's smbd with a 617 MB heap
(under 1 MB still allocated), at every start. With `.metadata_never_index`
at the share's root, the connection stays at ~4 MB.

The benchmark's earlier workload (`head -c 4G /dev/zero | tail`) failed at
2 GiB on both engines without the script noticing (busybox `tail`'s line
limit). It now uses Python and checks the workload finished.
